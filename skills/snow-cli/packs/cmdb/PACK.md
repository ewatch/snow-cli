# CMDB & CSDM Pack (`snow-cli`)

Opt-in pack for inspecting CMDB CI classes, CI relationships (`cmdb_rel_ci`), Identification and Reconciliation Engine (IRE) rules, and duplicate/orphan CI audits.

All commands below are read-only and use `snow-cli-ro`.

## 1. Key tables

| Table | What it stores | Key fields to project |
|---|---|---|
| `cmdb_ci` | Base Configuration Item table (all CI subclasses extend this) | `sys_id,name,sys_class_name,operational_status,install_status,discovery_source,serial_number,fqdn,ip_address,duplicate_of` |
| `cmdb_rel_ci` | Directed CI-to-CI relationships | `sys_id,parent.name,parent.sys_class_name,type.name,child.name,child.sys_class_name` |
| `cmdb_rel_type` | Relationship type definitions (`Runs on::Runs`, `Depends on::Used by`, etc.) | `sys_id,name,parent_descriptor,child_descriptor` |
| `cmdb_identifier` | IRE Identification Rules per CI class | `sys_id,name,applies_to,independent,active,description` |
| `cmdb_identifier_entry` | Criterion attribute sets & priority per Identification Rule | `identifier.name,identifier.applies_to,table,attributes,priority,allow_fallback,active` |
| `cmdb_related_entry` | Related-item identification entries | `identifier.name,table,attributes,referenced_field,condition,order,active` |
| `cmdb_reconciliation_definition` | IRE Reconciliation Rules (which discovery source wins per attribute) | `name,applies_to,discovery_source,attributes,priority,active` |
| `reconcile_duplicate_task` | De-duplication tasks generated by IRE / CMDB Health | `number,state,short_description,cmdb_ci.name,sys_created_on` |

## 2. Explore CI classes & distribution

```bash
# 1. Discover CI tables and inheritance
snow-cli-ro table find cmdb_ci_ --limit 50
snow-cli-ro table schema cmdb_ci_linux_server --extended

# 2. Count active CIs by concrete class and discovery source (no row download)
snow-cli-ro table stats cmdb_ci --query 'operational_status!=6' --group-by sys_class_name
snow-cli-ro table stats cmdb_ci_server --group-by discovery_source
```

## 3. Trace CI relationships (upstream & downstream)

```bash
# 1. Find the CI
snow-cli-ro table list cmdb_ci \
  --query 'nameLIKEprod-app-01' \
  --fields sys_id,name,sys_class_name,operational_status,discovery_source,duplicate_of --display-value both --limit 20

# 2. Inspect both outgoing (parent) and incoming (child) relationships
snow-cli-ro table list cmdb_rel_ci \
  --query 'parent=<ci_sys_id>^ORchild=<ci_sys_id>' \
  --fields parent,parent.name,parent.sys_class_name,type.name,child,child.name,child.sys_class_name \
  --limit 100
```

## 4. Diagnose IRE Identification & Reconciliation rules

Use when answering: "Why did Discovery/Import create a duplicate CI instead of updating?" or "Why did Discovery source B fail to overwrite attribute X?"

```bash
# 1. Walk the CI class hierarchy (e.g. cmdb_ci_linux_server -> cmdb_ci_unix_server -> cmdb_ci_server -> cmdb_ci_computer -> cmdb_ci_hardware -> cmdb_ci)
snow-cli-ro table list sys_db_object \
  --query 'nameINcmdb_ci_linux_server,cmdb_ci_unix_server,cmdb_ci_server,cmdb_ci_computer,cmdb_ci_hardware,cmdb_ci' \
  --fields name,super_class.name

# 2. Find Identification Rules across the class chain (most specific class wins!)
snow-cli-ro table list cmdb_identifier \
  --query 'applies_toINcmdb_ci_linux_server,cmdb_ci_unix_server,cmdb_ci_server,cmdb_ci_computer,cmdb_ci_hardware,cmdb_ci^active=true' \
  --fields sys_id,name,applies_to,independent,active --limit 20

# 3. Inspect ordered criterion attribute sets for the winning identifier
snow-cli-ro table list cmdb_identifier_entry \
  --query 'identifier=<identifier_sys_id>^active=true' \
  --fields priority,table,attributes,allow_fallback,active --order-by priority --limit 30

# 4. Check Reconciliation Rules controlling which discovery_source may update attributes
snow-cli-ro table list cmdb_reconciliation_definition \
  --query 'applies_toINcmdb_ci_linux_server,cmdb_ci_server,cmdb_ci_hardware,cmdb_ci^active=true' \
  --fields name,applies_to,discovery_source,attributes,priority --order-by priority --limit 50
```

## 5. Audit duplicate & orphan CIs

```bash
# CIs already flagged as duplicates
snow-cli-ro table stats cmdb_ci --query 'duplicate_ofISNOTEMPTY' --group-by sys_class_name

# Open de-duplication tasks
snow-cli-ro table list reconcile_duplicate_task \
  --query 'active=true' \
  --fields number,state,short_description,sys_created_on \
  --order-by -sys_created_on --limit 20

# Quick duplicate-name hotspot check on a specific class via Aggregate API
snow-cli-ro table stats cmdb_ci_server --query 'operational_status!=6' --group-by name --having 'count>1'
```

## 6. Gotchas

- **Child Identification Rules completely replace parent rules:** If a child class (e.g. `cmdb_ci_computer`) has its own active `cmdb_identifier`, it **does NOT inherit** the parent class's (`cmdb_ci_hardware`) identifier entries or related entries — only the child's entries apply!
- **Independent vs Dependent CIs:** Dependent CIs (`independent=false`, e.g. Network Adapters, Applications) cannot be identified without their required parent relationship defined in `cmdb_metadata_containment` / `cmdb_related_entry`.
- **Reconciliation rules block lower-priority sources silently:** If a discovery source has higher priority (lower `priority` number) for an attribute on `cmdb_reconciliation_definition`, updates from lower-priority sources are skipped by IRE without throwing an obvious error.
- **Query the concrete class when filtering subclass columns:** Querying `cmdb_ci` cannot directly filter on a field defined only on `cmdb_ci_server` (like `cpu_count`) — query `cmdb_ci_server` instead.
